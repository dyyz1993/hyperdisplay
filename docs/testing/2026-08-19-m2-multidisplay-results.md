# M2 实测记录：多虚拟屏 + 局域网/USB 双通道（2026-08-19）

环境：macOS 26.2 · Pixel 7 API 34 模拟器（arm64） · 华为 DBY2-W00 平板（锁屏状态）

## 1. 多屏协议回环（Python 模拟客户端，PASS）

```
STEP1 HELLO      → DISPLAYS(1×1920×1200) + WELCOME + CONFIG + 2514 frags（6s）
STEP2 CREATE     → DISPLAYS(2 屏) + WELCOME(1280×800) + CONFIG + 1469 frags
STEP3 SELECT 回屏1 → WELCOME(1920×1200) + 2133 frags（流切换含重建会话）
STEP4 DESTROY 屏2 → DISPLAYS(1 屏)
RESULT: PASS
```

## 2. 模拟器端到端（全新启动的模拟器）

- `HEVC 1280×800 · 30 fps · 链路 OK`，解码统计 **out=271/271**（输入即输出，零丢帧）。
- **输入闭环（硬证据）**：`adb input tap 1200 500` → host 日志
  `first input: move=(589.6, 370.4)` —— 与视图→流坐标 aspect-fit 映射的数学预期一致
  （点击中偏左 → 流坐标 589/1280 中偏左）。
- **多屏 UI E2E**：右上角「屏 1/1 ▾」→「新建（适配本机）」→ host 创建 **2264×1017**
  虚拟屏（= 模拟器原生横屏分辨率），客户端浮层变 `HEVC 2264x1017`、按钮 `屏 1/2 ▾`。

## 3. 重要更正：M1 的"光标闭环"证据作废

M1 记录中「tap 后画面出现光标」不能作为输入闭环证据——事后发现当时客户端存在
**NetworkOnMainThreadException**（Android 默认禁止主线程网络操作，触摸事件里的所有
send 全被静默丢弃），画面中的"光标"实为模拟器 guest 自身指针。M1 文档 §3 相应结论以本
文档 §2 的 host 侧坐标日志为准（修复后的真实闭环证据）。

## 4. 本轮发现并修复的缺陷

| # | 缺陷 | 修复 |
|---|---|---|
| 1 | 客户端所有主线程网络调用（触摸/看门狗/选屏）被 NetworkOnMainThreadException 静默丢弃 | 专用 HandlerThread 发送线程，全部出口包走它 |
| 2 | 流停止后重启：`now - snapshot` UInt64 下溢 → Swift 运行时 trap 整个 host 崩溃 | 加锁快照 + 会话重置归零 |
| 3 | host 编码会话重建后参数集变化，旧解码器从此解不出帧 | 客户端检测 csd 变化自动重建解码器 |
| 4 | 关键帧仅靠 configure 时的 csd-0，部分解码器不产出 | 关键帧在带内前置参数集 |
| 5 | PTS 全零 | 单调递增 PTS（33ms 步进） |

## 5. 模拟器已知限制（重要）

模拟器**长时间运行 / 多次创建解码器实例后**，MediaCodec 会整体性劣化：输入全部
dequeueInputBuffer 接受、输出永远 0 帧（HEVC 与 H.264 皆然，换新进程无效，只有重启
模拟器恢复）。此状态与本仓库代码无关，判定依据：

1. 同一份客户端组装出的码流落盘后 **ffmpeg 263 帧全解零错误**；
2. **全新启动**的模拟器上同一 build 渲染 30fps（out=271/271）；
3. 劣化后 H.264/HEVC、新进程、旧进程全部同样停摆 → 模拟器镜像级状态问题。

结论：**模拟器只适合"刚启动时"的验证；一切最终验证以真机为准。**

## 6. 真机（华为 DBY2-W00）状态

- APK 安装成功；锁屏状态下 app 可启动并多次向 host 发起 HELLO（2800×1840 over WiFi）。
- 锁屏后台运行受厂商网络/电源管控影响，连接不稳定（HELLO 后静默被 prune）；
  且无第三方 logcat（华为日志开关），已加入 status.txt 状态落盘通道（run-as 可读）。
- **待用户解锁后**完成：画面/触摸/多屏切换真机验证 + USB 网络共享延迟对比实测。
