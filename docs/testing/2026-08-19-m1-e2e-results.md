# M1 端到端实测记录（2026-08-19）

环境：macOS 26.2 (Tahoe, arm64) · Pixel 7 API 34 模拟器（arm64） · 同机回环 / 局域网 WiFi
主机侧 TCC：屏幕录制 + 辅助功能均已在执行终端授权（未授权时 host 菜单栏会显示缺权限项并阻塞管线启动）。

## 1. CGVirtualDisplay 可行性（--check，无需任何权限）

```
created display id=6 1920x1200, 等待生效 → active 列表出现：
  #0 id=1 1512x982 origin(0,0) [main]
  #1 id=6 1920x1200 origin(1512,0) [hyperdisplay]
explicit destroy → 屏消失
--check PASSED
```

关键实现事实（踩坑记录）：

- Swift 里 `NSClassFromString("CGVirtualDisplay") as? @objc protocol.Type` **在私有类上必然失败**
  （ObjC 运行时按「正式协议遵守」判定，私有类没声明遵守我们的协议）。类本身存在
  （探针 `NSClassFromString` 可直接拿到）。解法：SwiftPM 加 ObjC shim target（`HyperdisplayObjC`），
  用 class-dump 头文件直接声明并调用——DeskPad 同款做法。
- 当前接口是 **modes 数组**（`CGVirtualDisplayMode(width:height:refreshRate:)` + `settings.modes`），
  网上流传的旧接口（`pixelWidth/pixelHeight/refreshRate` 直挂 settings）已过时。

## 2. 本机回环（Python 模拟客户端，UDP 127.0.0.1:5277，默认档 1920×1200@60）

```
WELCOME: proto=1 codec=1 (HEVC) 1920x1200 fps=60
CONFIG: codec=1 params=83B            ← VPS+SPS+PPS (Annex-B) 随每个关键帧下发
frames complete=175 keyframes=1 gap-events=0   （6 秒窗口）
effective fps ≈ 29.2                  ← 静态桌面内容驱动采集，29fps 为真实值
video bitrate ≈ 3.9 Mbps              ← 8 Mbps 上限内，无填充
RESULT: PASS
```

## 3. 模拟器端到端（Pixel 7 API 34，host 1280×800@60 · 1 Mbps 降档）

- Android 客户端 `am start -e host 10.0.2.2:5277` 自动连接。
- 状态浮层实测读数：`HEVC 1280x800 · 30 fps · 链路 OK`（渲染 fps 为解码输出实测值）。
- 视觉确认（截图见 `assets/hd_emu_before.png` / `hd_emu_after.png`）：
  - 画面 = 虚拟屏壁纸（雪山湖泊）全屏渲染，正确 letterbox；
  - **⚠ 更正（2026-08-19）**：原记录的「tap 后画面出现光标」不能作为输入闭环证据——
    当时客户端存在 NetworkOnMainThreadException（主线程网络调用被 Android 静默丢弃，
    触摸发送全部失败），截图中的光标实为模拟器 guest 自身指针。真实输入闭环证据
    （修复后，host 侧坐标日志）见 `2026-08-19-m2-multidisplay-results.md` §2。

## 4. 过程中发现并修复的缺陷

| # | 缺陷 | 修复 |
|---|---|---|
| 1 | VideoToolbox 输出回调拿到的 refcon 是**每帧** sourceFrameRefcon（建会话 refcon 不传给回调），初版传 nil 导致所有编码输出被丢弃、inFlight 卡满后编码器假死 | `EncodeFrame` 每帧传 `passUnretained(self)` |
| 2 | 静态虚拟屏下 SCK 只发 idle(0)+buffer 事件，complete(1) 事件无缓冲；客户端中途加入时 PLI 等不到新源帧 | CaptureEngine 缓存最新帧；keyframeReq/HELLO 时 `replayLastFrame()` 重编码出 IDR（不主动为静态内容出码率） |
| 3 | 客户端连接后若 host 无新帧则永远收不到 CONFIG | Android 加视频看门狗：链路通且无 csd 时每 700ms 请求 IDR |
| 4 | 帧成功投递后 `fragments` 清空导致 `!isComplete()` 误判为丢弃，stall 检查在静态桌面周期性误触 | 增加 `deliveredCurrent` 标记 |
| 5 | 模拟器 slirp NAT 在 4Mbps UDP 下大量丢分片（真机 WiFi 无此问题，待平板复验） | 客户端接收缓冲 4MB；模拟器验证降档 1280×800@1Mbps |

## 5. 真机状态

- **华为 DBY-W00 平板（192.168.0.10）**：APK 已安装；app 在锁屏后仍能连接（host 日志见 2800×1840 HELLO + IDR 下发），
  但设备有 PIN 锁 + 需人工解锁后才能做画面/触摸验证。**待用户解锁后复验。**
- **Redmi Note 7**：MIUI「USB 安装」拦截，装包被系统级阻断。需在开发者选项开启「USB 安装」。

## 6. 结论

M1 目标在 macOS host + 模拟器上完整达成：造屏→采集→HEVC→UDP→解码渲染→触摸闭环，全部有客观证据
（帧计数、协议报文、host 侧输入坐标日志）。待平板解锁后补真机 WiFi 数据（延迟/丢包/fps）。
