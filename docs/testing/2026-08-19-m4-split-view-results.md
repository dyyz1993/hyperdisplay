# M4 实测记录：平板分屏多路显示（2026-08-19）

环境：macOS 26.2 · 华为 DBY2-W00（2800×1840，2.4GHz WiFi）

## 设计要点（用户需求 → 实现）

> 「多个屏幕也得让平板的画面一分为二，否则意义不大；比例和分辨率应该根据平板画面来调整。」

- **分屏 = 虚拟屏尺寸取平板对应区域的物理像素**：左右分屏 → host 建两块
  1400×1840 的屏，每格像素 1:1，总像素 ≈ 平板原生单路 → **带宽不升反平**。
- macOS 会把两块虚拟屏并排排在 Mac 桌面 → 平板的空间布局 ≈ Mac 的显示器排列。

## 协议 v3

- VIDEO_FRAG / CONFIG / WELCOME / INPUT×3 / NACK / KEYFRAME_REQ 全部携带 `displayId u16`
  （KEYFRAME_REQ 0xFFFF=全部）；一条 UDP 多路复用。
- 新增 `SUBSCRIBE_DISPLAYS [count u8][id u32 × n]`：订阅集整体切换（分屏模式）；
  `SELECT_DISPLAY` 保留为单屏语义。

## host

- Client 订阅集 `Set<displayId>`；输入/NACK/关键帧按报文 displayId 路由到对应屏的
  injector / 分片缓存 / 编码会话（不再按发送者推断）。
- 无订阅者的流由周期 tick 自动停（已有机制复用）。

## 客户端

- 每屏一条独立管线（FrameAssembler + MediaCodec + StreamView）；
- 布局切换（单屏 / 左右 / 上下）：按平板区域尺寸**先建缺的屏 → DISPLAYS 推送凑齐后
  整体 SUBSCRIBE → 回收不再使用的同尺寸自建屏**（修复了重复计数导致的第三块孤儿屏）；
- 触摸按区域命中路由到对应 displayId，坐标在每个区域内 1:1 映射。

## 实测（真机）

- 干净流程：连接（默认单屏）→「布局 ▾ → 左右分屏 → 应用」→ host **恰好新建 2 块
  1400×1840**（无孤儿屏）→ 平板浮层 **`51 fps · 2 屏分屏 · 链路 OK`**（新屏内容动画期）
  → 静态回落至内容驱动低帧率（诚实值）。
- 视觉取证（截图）：屏幕左右两区域 + 清晰分界线，「屏×2」按钮在位；两区域内容
  同为壁纸（虚拟屏初始即壁纸）。
- 触摸分区路由：与 M3 单屏输入共用同一路径（displayId 字段化）；静态桌面下光标
  不显示属内容驱动特性，动态内容下的光标定位留待日常使用复验。

## 已知边界

- 分屏切换时虚拟屏销毁重建（尺寸变化），已放置窗口会被 macOS 挪回主屏。
- 四分屏 / 主屏+缩略图：布局框架已支持 N 区域，UI 预留后续。
- 每路一解码器：2 路 HEVC 硬解并发真机无压力；4 路时建议降分辨率。
